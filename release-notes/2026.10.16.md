# Sans Emoji 2026.10.16

Prepared on October 16, 2026. Changes since `v2026.10.15`. Store submission, approval, and signing are separate steps.

## Compatibility

- Require desktop Firefox 142 or later, up from 140. Mozilla's validation of the 2026.10.15 package warned that Firefox for Android 140, the Android minimum it derived from the desktop minimum, predates Android support for the required `data_collection_permissions` key, which arrived in version 142. Android distribution remains disabled. Mozilla's release calendar lists 153 as the current ESR and 115 as the only older ESR still supported, so Firefox 140 ESR and 141 no longer receive updates.
- The extension's code is unchanged. The bundled script and stylesheet are byte-identical to 2026.10.15; only the manifest's version and Firefox minimum differ. Chrome behavior is unchanged.

## Tooling and documentation

- Local extension validation now fails on every linter warning, including the Android minimum-version warning it previously skipped, so it reports the same warnings as Mozilla's validation. esbuild targets Firefox 142.
- Update the README, support page, and Firefox submission reference for the new minimum.

## Validation

Validated on October 16, 2026, with Node.js 24.18.0 and pnpm 12.10.1:

- `pnpm install --frozen-lockfile` and `pnpm package` passed. Packaging checked all three strict TypeScript environments, Biome, 101 unit tests at 100% statement, branch, function, and line coverage across `src/`, `tooling/`, and `scripts/`, a clean build, and extension validation with web-ext 10.6.0 (addons-linter 10.10.0): zero errors, warnings, or notices. No warnings were skipped.
- With the manifest temporarily set back to `140.0`, local validation failed with `KEY_FIREFOX_ANDROID_UNSUPPORTED_BY_MIN_VERSION`, the warning in Mozilla's report for 2026.10.15.
- `src/` and the stylesheet are unchanged since `v2026.10.15`. Builds targeting Firefox 140 and 142 produced identical SHA-256 hashes for `content.js` and `content.css`.
- `pnpm exec playwright test` passed all 80 Chromium 156.0.8078.4 and Firefox 157.0 fixture checks against the versioned build.
- Store images were not regenerated; the 2026.10.15 images remain current because the extension's appearance and behavior are unchanged.

## Known limitations and submission checks

- Mozilla's validation of the 2026.10.16 package has not been run. Local validation is clean, but AMO may run a newer linter; read its report before submission.
- Live signed-in Jira, Confluence, and Bitbucket editor checks recorded as pending for 2026.10.15 remain pending: punctuation spacing variants, Enter/Tab, undo/redo, mentions, slash commands, and the toolbar picker. The extension code is unchanged, so a check of either build covers both.
- Chromium fixtures load the unpacked extension; Firefox fixtures inject its compiled script and stylesheet. They do not verify Firefox add-on installation or signing. The Chrome 120 and Firefox 142 minimum versions have not been tested; desktop Firefox 142+ is required and Android distribution is not enabled.
- Behavior limitations are unchanged from [2026.10.15](2026.10.15.md#known-limitations-and-submission-checks): an editor that ignores synthetic Escape may retain an invisible autocomplete state that consumes Enter or Tab; the modern hiding rule applies throughout the document while any `[data-query-prefix=":"]` element exists, so simultaneous menus are not independently scoped; a suggestion panel without emoji items can paint after its query disappears; internal markup changes can affect support; custom domains remain outside scope.
