# Sans Emoji 2026.10.10

First tagged release, prepared for store submission on October 13, 2026. The package and manifest version is `2026.10.10`; this tag includes the initial feature set and the refinements completed before tagging. Store publication is a separate step.

## Features

- Suppress colon-triggered emoji autocomplete on HTTPS atlassian.net, atlassian.com and bitbucket.org pages, including their subdomains and matching frames.
- Hide recognized suggestion panels from their first frame, including during input-method composition and delayed cancellation. Ask the editor to cancel through its own Escape handler without rewriting text.
- Preserve French punctuation spacing, including ordinary and non-breaking spaces. Intentional colon searches such as `:smile` are suppressed too; use the editor's toolbar picker to insert emoji.
- Keep existing emoji, mentions, slash commands, and the separate toolbar emoji picker available in the tested editor fixtures.
- Run automatically with no settings or toolbar popup. Process editor content locally, with no telemetry, saved data, or network requests from the extension.

## Development and distribution

- `pnpm build` creates one unpacked `dist/` for desktop Chrome and Firefox. Replace development installations that still point to the old browser subfolders.
- `pnpm package` creates `dist/sans-emoji.zip` for either store and `dist/sans-emoji-sources.zip` for Mozilla source review. Fixed ZIP timestamps and sorted paths support reproducible builds from the included sources without Git metadata.
- Use strict TypeScript 7 with separate browser, Node tooling, and test environments, pnpm 12 tooling, extension validation, and CI actions pinned to verified commits.
- Include the MIT license, store submission copy, build instructions, public documentation, and these release notes in the appropriate distribution or review archives.
- Publish the overview, privacy policy, and support pages at [the project website](https://sebastienguillon.github.io/sans-emoji/). The site explains manual installation, domain compatibility, troubleshooting, and local data handling.

## Known limitations and submission checks

- Live signed-in Atlassian editors and their real undo/redo behavior have not been validated. Complete the manual editor checks in the README before store submission.
- Firefox add-on installation and signing are not covered by the injected Firefox fixtures. Firefox requires version 140+; permanent installation in standard releases requires Mozilla signing. Android distribution is not enabled.
- If an editor ignores synthetic Escape, its suggestions remain hidden but its autocomplete state may still consume Enter or Tab. Press Escape or disable the extension and refresh the page if this occurs.
- The modern suppression rule applies throughout the document while a colon query exists; simultaneous menus in multiple editors are not independently scoped.
- Internal Atlassian markup changes may require selector updates. Custom company domains and unrelated frame URLs remain outside scope.
- Store listing copy is prepared, but release screenshots and promotional artwork have not been added. No Chrome Web Store or Mozilla Add-ons submission has been completed as part of this release preparation.
